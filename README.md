# 家事ルーレット

日常の家事を「自分で選ぶ」のではなく、今使える時間と今日のコンディションに合わせてルーレットが提案してくれるアプリです。「何をやろうか考える面倒」をなくし、ゲーム感覚で家事に取り組めることを目指しています。

## 実際のサイトはこちら
https://housework-roulette.vercel.app/

## 使い方

1. ログイン（初めての方はサインアップ）
2. ホーム画面で「使える時間」と「今日のコンディション」を選び、ルーレットを回す
3. 表示された家事を「これをやる」か「もう一度回す」で選ぶ
4. タイマー画面でSTART → 00:00からカウントアップしながら家事を実施(一時停止・再開も可能)
5. 所要時間の目安に達するとアラームが鳴る(カウントは止まらない) → 実際に終わったら「完了」を押すと完了画面が表示され、実際にかかった時間が履歴に記録される

## 技術スタック

- Next.js（App Router）/ React 19 / TypeScript
- Tailwind CSS 4.x + shadcn/ui（base-nova, Base UIベース）
- Prisma（Neon / PostgreSQL、開発・本番共通）
- NextAuth（Auth.js） Credentials Provider によるメール・パスワード認証
- Vitest + React Testing Library

## セットアップ

```bash
npm install
cp .env.example .env   # DATABASE_URL・DIRECT_URL・AUTH_SECRETを設定する
npm run prisma:migrate # Neonのデータベースにテーブルを作成
npm run prisma:seed    # デモユーザー(demo@example.com / password1234)と初期家事を投入
npm run dev
```

`.env` の項目:

| 変数名 | 説明 |
| --- | --- |
| `DATABASE_URL` | Neon(PostgreSQL)の接続文字列。アプリ実行用のプーリング接続(ホスト名に `-pooler` が付く方) |
| `DIRECT_URL` | Neonの直接接続文字列。`prisma migrate` はプーリング接続を通せないためマイグレーション専用に使用 |
| `AUTH_SECRET` | NextAuthのセッション署名鍵。`openssl rand -base64 32` などで生成 |

`NEXT_PUBLIC_` プレフィックスの環境変数としてDB接続情報を公開しないこと。

### データベース(Neon / PostgreSQL)

開発・本番ともにNeonを使用します。PostgreSQLはネイティブに外部キー制約をサポートするため、スキーマは通常のリレーション定義のままです。

Neonのサーバーレス環境では同時接続数が多くなりやすいため、`schema.prisma` の `datasource` に `url`(プーリング接続、アプリ実行用)と `directUrl`(直接接続、マイグレーション専用)を分けて定義しています。`prisma migrate dev` / `deploy` は `directUrl` を自動的に使用します。

スキーマ変更は通常のPrisma Migrateフローで反映します:

1. `schema.prisma` を変更する
2. `npm run prisma:migrate` でマイグレーションファイルを生成し、開発用Neonデータベースに適用する
3. 生成された `prisma/migrations/` 配下のSQLをコミットする
4. 本番では `npm run prisma:deploy`(`prisma migrate deploy`)で同じマイグレーションを適用する

### Vercelへのデプロイ

1. Neonでプロジェクト(データベース)を作成し、プーリング接続文字列と直接接続文字列を発行する
2. Vercelプロジェクトの環境変数に `DATABASE_URL`(プーリング接続)・`DIRECT_URL`(直接接続)・`AUTH_SECRET` を設定する
3. `npm install` 時に `postinstall` スクリプトが `prisma generate` を実行するため、追加のビルド設定は不要
4. デプロイ前(またはデプロイ後に一度)に `npm run prisma:deploy` を本番用の `DATABASE_URL`/`DIRECT_URL` に向けて実行し、テーブルを用意しておく(Vercelのビルドステップではマイグレーションを自動実行しない)

## ルーレットの抽選ロジック

ロジックは `src/lib/roulette.ts` に純粋関数として実装されており、`tests/unit/roulette.test.ts` で検証しています。

- **時間フィルタ**: 選択した時間以内(以下)でできる家事だけを候補にする。例えば「5分」を選んだ場合、5分の家事だけが候補になり、10分や15分の家事は絶対に選ばれない。候補が1件もない場合は、最も所要時間が短い家事群にフォールバックする
- **コンディションスコア**: コンディション(元気〜かなり疲れた)×難易度(1〜5)の相性を手動テーブルで定義。疲れているほど低難易度が、元気なほど高難易度も出やすくなる
- **直近実施ペナルティ**: 直近5件の履歴に含まれる家事は出現重みを最大50%減らす(完全には出なくならない)
- コンディションスコア×ペナルティに下限値を設けたうえで、時間フィルタを通過した候補内で重み付きランダム抽選を行うため、「時間内に収まる家事の中で、コンディションに合う家事ほど出やすいが、何が出るかは完全には分からない」仕様になっている
- 「もう一度回す」・連続表示の回避は、直前に表示した家事を候補から除外して再抽選することで実現している
- ルーレット演出中に流れる候補名も、時間フィルタを通過した家事だけに限定している(選ばれない家事を見せて誤解させないため)

## タイマーの仕様

- カウントダウンではなく、00:00から数え上げるストップウォッチ形式
- 所要時間の目安に達するとアラーム音(Web Audio APIで生成したビープ音)を1回鳴らすが、カウントは止めない
- 実際に家事が終わったタイミングでユーザーが「完了」を押すと、そこで初めて完了扱いになり、実際にかかった時間が履歴に記録される

## データモデル

- `User`: メールアドレス・パスワードハッシュを持つユーザー。家事・履歴はすべてこのユーザーに紐づき分離される
- `HouseworkTask`: ユーザーごとの家事マスタ(家事名・所要時間・難易度・カテゴリ・説明)。削除は論理削除(`isActive`)とし、履歴の整合性を保つ
- `HistoryEntry`: 完了した家事の履歴。家事名・所要時間は実施時点の値をスナップショット保存するため、家事が削除されても履歴は壊れない

新規ユーザー作成時（サインアップ）には、`src/lib/defaultTasks.ts` に定義された初期10家事が自動的に登録されます。
